# Preview · 订单状态与财务延伸

对照 **FR-ORD 订单履约** 与 **FR-PAY/FIN 退款、发票**，Preview 在履约状态之外增加财务展示状态，并与业务单据联动。

## 履约主流程

```
PENDING_PAYMENT → CONFIRMED → READY_FOR_PICKUP → IN_USE
  → RETURN_PENDING_SETTLEMENT → SETTLED → COMPLETED
```

管理端订单详情可 **推进下一履约状态**（财务状态不通过该按钮推进）。

## 提车 / 开始服务（C 端）

| 服务方式 | 用户操作 | API |
|---|---|---|
| 自驾 / 包车 | **确认租车服务开始**（统一按钮） | `PUT /api/v1/orders/{id}/pickup` |

状态推进（与正式 API 一致）：`CONFIRMED` → `READY_FOR_PICKUP` → `IN_USE`（单次确认直达使用中）。

前置条件（Preview）：

- 预付订单须已付清；后付费已确认即可
- 包车须已分配 `driverId`

实现：`packages/shared/src/order-fulfillment.ts`；H5 订单列表/详情快捷按钮。

演示种子：`ORD20260530007`（待取车自驾）、`ORD20260530008`（待出车包车）。

## 财务延伸状态

| 状态 | 中文 | 触发条件（Preview Mock） |
|---|---|---|
| INVOICE_PENDING | 开票中 | 存在 status=PENDING 的发票且订单已结算/完成 |
| INVOICE_ISSUED | 已开发票 | 存在 status=ISSUED 的发票 |
| REFUND_PENDING | 退款处理中 | 存在 PENDING/APPROVED 退款单 |
| REFUND_PARTIAL | 部分退款 | 已完成退款金额 < 已付金额 |
| REFUND_SUCCESS | 退款成功 | 已完成退款金额 ≥ 已付金额 |

实现：`packages/shared/src/order-status.ts`

- `syncOrderStatusFromRelations()` — 计算展示状态  
- `reconcileOrderStatusInStore()` — 写回 `store.orders`  
- `buildOrderStatusBadges()` — 详情页辅助标签（已开发票、退款成功等）

## 管理端操作与同步

| 操作位置 | 动作 | 订单效果 |
|---|---|---|
| 电子发票 | 单条/批量 `status=ISSUED` | 同步 INVOICE_ISSUED |
| 支付退款 | 退款 `status=COMPLETED` | 同步 REFUND_SUCCESS / PARTIAL |
| H5 | POST `/api/v1/invoices` | 演示即时开具 + 同步 |
| 订单列表 | GET `/api/v1/orders` | 列表加载前全量 reconcile |

## 订单详情关联（管理端）

`GET /api/v1/orders/{id}` → `OrderDetail`：

| 字段 | 说明 |
|---|---|
| `relations.userHref` | `/users?highlight=` |
| `relations.vehicleHref` | `/vehicles/{id}/history` |
| `relations.driverHref` | `/staff?highlight=` |
| `statusBadges` | 发票/退款/事故辅助标签 |

UI：`apps/admin/src/components/shared/OrderDetailView.tsx`
