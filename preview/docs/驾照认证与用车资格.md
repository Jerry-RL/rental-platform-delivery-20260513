# Preview · 驾照认证与用车资格

对照正式需求 **FR-USER-013 / FR-USER-014** 与 OpenAPI `openapi-users-v1.yaml`，在方案演示版中实现自驾前置校验闭环。

## 业务规则（摘要）

| 编号 | 说明 |
|------|------|
| FR-USER-013 | 用户上传驾驶证（证号、准驾车型、领证/有效期、正反面图）；平台审核；过期禁止自驾 |
| FR-USER-014 | 下单前聚合校验：实名通过 + 驾照有效（自驾） |
| BR-自驾 | `serviceMode = SELF_DRIVE` 时触发；`WITH_DRIVER` **不校验客户驾照** |
| BR-多台自驾 | **N 台自驾 = N 名本次自驾司机**，各上传其驾照（`SELF_DRIVE_DRIVER`），**非**账户本人驾照复用 |
| BR-单台自驾 | 可登记「本次自驾司机」驾照，或沿用账户「本人驾照」（`ACCOUNT_HOLDER`） |

包车规则详见 [服务方式与下单规则.md](./服务方式与下单规则.md)。

## 错误码（`api-error-codes-v1.md`）

| code | 含义 | 典型场景 |
|------|------|----------|
| 3003 | LICENSE_EXPIRED | 驾照已过期 |
| 3004 | IDENTITY_NOT_VERIFIED | 未实名或实名未通过 |
| 3005 | DRIVER_NOT_VERIFIED | 未上传/未通过驾照 |
| 3002 | （演示）审核中/驳回 | 待审或驳回文案 |

## Mock API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/users/{userId}/license` | 当前驾照；`?vehicleId=` 取该车绑定驾照 |
| GET | `/api/v1/users/{userId}/licenses` | 用户全部驾照列表 |
| POST | `/api/v1/users/{userId}/license` | 本人：`role=ACCOUNT_HOLDER`；司机：`vehicleId`+`driverName`+`role=SELF_DRIVE_DRIVER` |
| POST | `/api/v1/users/{userId}/realname` | 提交实名 → `PENDING` |
| GET | `/api/v1/users/{userId}/eligibility?serviceMode=SELF_DRIVE\|WITH_DRIVER` | 用车资格快照 |
| GET | `/api/v1/drivers?city=` | 包车指派司机（Preview 补充） |
| POST | `/api/v1/orders/quote` | 自驾时资格不通过则失败 |
| POST | `/api/v1/orders` | 同上 |
| GET | `/api/v1/admin/licenses` | 管理端审核列表 |
| PUT | `/api/v1/admin/licenses/{id}/approve` | 通过 |
| PUT | `/api/v1/admin/licenses/{id}/reject` | 驳回（body: `rejectReason`） |

请求上下文：`previewRequest` 自动附带当前登录 `userId`（从 token 解析）。

## H5 演示路径

1. 登录 **13600136097**（未上传驾照）→ 选车自驾 → 提示去 `/license` 上传  
2. 提交后登录管理端 → **用户与认证 → 驾照审核队列** → 通过  
3. 回到 H5 刷新资格 → 报价/下单成功  
4. 租车篮勾选 **2 台及以上自驾** → 结算页按车牌逐台「上传驾照」→ 管理端逐条审核 → 全部通过后批量下单  
4. **13600136098** 演示过期（3003）；**13600136000** 演示待审（3002）  
5. 切换下单页 **包车带司机** → 无需驾照即可报价（`eligibility?serviceMode=WITH_DRIVER`）
