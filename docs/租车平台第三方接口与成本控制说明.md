# 租车平台第三方接口与成本控制说明

版本：v1.0  
日期：2026-05-18

## 1. 对接范围

本阶段涉及两类第三方接口：

- 违章查询：聚合数据开放平台 API
- GPS定位：已联系厂商平台 API

## 2. 供应商接口清单

| 类别 | 供应商 | 核心用途 | 调用方式 |
|---|---|---|---|
| 违章 | 聚合数据 | 违章查询（单车/批量封装） | HTTPS REST |
| GPS | 厂商平台 | 实时定位、轨迹、在线状态 | HTTPS REST |
| 地图 | 待确认 | 位置输入、坐标解析、轨迹展示 | SDK/API |

## 3. 接口接入设计

### 3.1 统一适配层

- 新增 `Integration Adapter` 层，隔离供应商协议差异
- 内部统一模型：`provider`、`request_id`、`status`、`cost`、`raw_payload`
- 避免业务服务直接依赖供应商字段

### 3.2 接口治理

- 重试：网络错误与5xx支持指数退避重试
- 熔断：连续失败触发熔断，快速失败保护核心链路
- 限流：按租户与接口维度限流
- 告警：错误率、超时率、成本异常均触发告警

## 4. 成本模型与配额策略

### 4.1 成本模型

- 违章查询按单车单次计费（估值 0.04~0.05 元/车/次）
- 批量任务总成本 = 查询成功车辆数 * 单车单次单价
- GPS费用按厂商套餐和调用量执行（以商务合同为准）

### 4.2 配额策略（建议默认）

- 默认每月免费查询 2 次（按租户）
- 超额策略可配置：
  - `DENY`：直接拒绝
  - `APPROVAL`：审批后执行
  - `PAID`：继续执行并记账

## 5. 数据落库建议

### 5.1 关键数据表

- `violation_query_quota`：月度配额、已用次数、策略
- `violation_query_task`：批量任务主表
- `violation_query_item`：车辆级结果明细
- `integration_call_log`：第三方调用日志
- `integration_cost_ledger`：第三方成本台账

### 5.2 核心字段

- 幂等：`idempotency_key`
- 审计：`operator_id`、`request_id`、`trace_id`
- 成本：`unit_cost`、`quantity`、`total_cost`
- 错误：`error_code`、`error_message`

## 6. 接口流程伪代码

```pseudo
FUNCTION callProviderWithGovernance(provider, endpoint, payload):
  key = makeIdempotencyKey(provider, endpoint, payload)
  IF existsSuccessLog(key):
    RETURN cachedResult(key)

  TRY:
    response = httpCall(provider, endpoint, payload, timeout=3s)
    normalized = normalize(provider, endpoint, response)
    writeCallLog(key, provider, endpoint, "SUCCESS", normalized.cost)
    RETURN normalized
  CATCH timeoutOr5xx:
    retryResult = retryWithBackoff(max=3)
    IF retryResult.success:
      writeCallLog(key, provider, endpoint, "SUCCESS_RETRY", retryResult.cost)
      RETURN retryResult

    openCircuitIfNeeded(provider, endpoint)
    writeCallLog(key, provider, endpoint, "FAILED", 0)
    RETURN error("PROVIDER_UNAVAILABLE")
```

## 7. 地图授权与合规建议

- 先完成法务与商务确认，再启用高风险地图能力
- 未确认授权阶段仅启用必要能力（地理编码/定位输入）
- 轨迹展示优先走 GPS 厂商提供能力，减少独立地图授权压力
- 合规留痕：保留“能力启停记录、授权证明、策略变更日志”
